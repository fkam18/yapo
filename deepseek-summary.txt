---

**Project:** Yapo (Yet Another Personal Orchestrator) – a home-lab LLM job orchestrator.
**Goal:** Manage stateless LLM jobs via a folder-based job pool, with MCP tools (memory, summarisation, web search, shell commands), GPU energy management, and automatic routing.

---

## Core architecture
- `yapo.py` – main scheduler loop; picks ready jobs, enforces server/tool capacity, handles GPU power (WoL/suspend).
- `jobber.py` – serialised CRUD for job folders; acquires `jobber.lock`.
- `runner.py` – executes a single job: routes (if no model), calls LLM, parses JSON output, creates tool children, propagates results, enforces loop guard.
- `init.py` – entry point: creates a main job with optional `--mtype` (model type) and `--rag` pre‑fetch.
- `config.py` – loads `config.toml`, provides `get_model()`, `get_server()`, `get_tool()`, etc.

## Job states & folders
`jobs/{ready,processing,pending,done,error}/<qno>/`
Each job folder contains: `job.toml`, `prompt.txt`, `context.txt`, `output.txt`, `full_prompt.txt`, optional `tool_call.json`, and `parent.<qno>` / `sub.<qno>` marker files.

## Configuration (`config.toml`)
- `yapo_root` (runtime data), `workspace` (file ops), `compact_size_kb`.
- `[[servers]]` – name, url, schedulable, max_jobs, mac_address, suspend_command.
- `[[models]]` – name, type (embed/summarise/router/code/others/vl), server, tool_allowed, temperature, max_tokens, repeat_penalty.
- `[[mcp_servers]]` – name, transport, command, args, env, protocol ("simple" or "jsonrpc").
- `[[tools]]` – name, description, parameters, concurrent_calls, timeout_seconds, mcp_server, mcp_tool.
- `[gpu_schedule]` – timezone, on_demand, idle_timeout_seconds, windows.

## LLM Prompt template (built by `runner.build_prompt`)
XML‑like sections: `<GOAL>`, `<CONTEXT>`, `<TOOLS>`, `<RULES>`, `<TASK>`.
Rules include JSON output format (tool call or done), dynamic convergence instructions (turn‑based), and restrictions (e.g., no shell operators in `run_command`).

## LLM Output parsing
Expects JSON: `{"tool": "...", "arguments": {...}}` or `{"done": true, "answer": "..."}`.
Runner now uses a robust `extract_json()` that strips markdown fences and extracts the first valid JSON object.

## Tool system & MCP
Three MCP servers:
- `yapo-mcp` (stdio) – route_prompt, mem_write, mem_read, summarise_text.
- `searxng-mcp` (stdio via custom wrapper `web_search_mcp.py`) – web_search.
- `shell-mcp` (stdio) – run_command, with command whitelist and metacharacter blocking.

Tools are defined in `config.toml` with `mcp_server`, `mcp_tool`, and `protocol`. Runner calls MCP tools via stdio subprocess, respecting protocol.

## Loop guard & convergence
- Total tool‑call cap: after 5 calls, force `done`.
- Dynamic prompt: as turn number increases, the prompt becomes increasingly insistent to produce a final answer.

## GPU energy management
- `yapo.py` checks server reachability; sends Wake‑on‑LAN if needed (on‑demand or within schedule window).
- Tracks `gpu_woken_by_yapo` flag and `last_gpu_job_end` timestamp.
- After idle timeout, if Yapo originally woke the GPU, it executes `suspend_command` (SSH with key, passwordless sudo).

## Auxiliary tools
- `catjob.py <qno>` – displays job state and output.
- `catanswer.py` – pipes from `catjob.py` and extracts the `answer` field (plain text).
- `dashboard.py` – web dashboard on port 3388, auto‑refreshes queue list, shows job details on click.
- `test_all_tools.sh` / `test_model.sh` – test scripts for MCP tools and models.

## Current status & recent fixes
- Router works with `qwen2.5:3b` on NUC; main models on GPU (Gemma4:9b for "others", qwen3coder30b for "code", vl2 for vision).
- JSON extraction robust against markdown fences.
- Loop guard prevents infinite tool calls; dynamic convergence makes model converge.
- Web search works via custom SearXNG wrapper; shell commands restricted to whitelist.
- GPU suspend still needs passwordless sudo setup on remote host.
- Venv issue: MCP servers should use full path to venv Python (`/home/fkam/apps/yapo/venv/bin/python3`) in `config.toml` commands.

## Key naming conventions
- **Job type** (`job.toml`): `"main"` or `"tool"`.
- **Model type** (`config.toml`): `"code"`, `"others"`, `"vl"`, `"embed"`, `"summarise"`, `"router"`.
- CLI flag for forcing model type: `--mtype`.
